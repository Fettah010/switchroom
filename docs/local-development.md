# Local development

## Prerequisites

- Node.js 22.12 or newer. `.nvmrc` pins Node 24 for CI; local verification was also run on Node 26.
- npm 11 or newer.
- A modern desktop browser for manual checks.

## Install

```bash
npm ci
```

The dependency tree includes Vite, React, the Cloudflare Vite plugin, Wrangler, Vitest, Playwright and the lint/format toolchain. `package.json` records the install-script approvals needed by `esbuild` and `workerd`.

## Run the app

```bash
npm run dev
```

Vite prints the URL, normally `http://localhost:5173`. Development builds expose `window.__switchroom.engine` for diagnostics; production builds do not.

## Playwright

Install the browsers once:

```bash
npx playwright install chromium
# Optional, for the full local matrix:
npx playwright install firefox webkit
```

`npm run test:e2e` starts the Vite dev server on `127.0.0.1:4173` and runs 15 tests in Chromium. `npm run test:e2e:all` runs Chromium, then Firefox, then WebKit sequentially; launching all three engines at once exhausted the local WebKit process on Windows, so the matrix script intentionally avoids that. You can also target one project directly:

```bash
npx playwright test --project=firefox
npx playwright test --project=webkit --workers=3
```

The suite's global setup writes deterministic fixtures to `tests/e2e/fixtures/` before each run. The folder is ignored by git and regenerated by `npm run fixtures`. It contains:

- matched 4-second WAV tones (`original.wav`, `edited.wav`);
- a 3.0 s / 2.4 s mismatch pair;
- a 1.2 s / 1.0 s short pair for end-of-playback checks;
- a zero-byte `empty.wav`;
- `notes.txt` with an unsupported extension;
- `invalid.mp3` containing text instead of audio.

All fixtures are generated sine tones. No external audio sample, licence or network stream is involved.

### WebKit on Windows

Playwright WebKit 27.2 on Windows reports WAV support but does not decode local audio in this environment. The audio-flow specs call `skipAudioFlowOnWindowsWebkit()` and are reported as skipped with a message, not passed. WebKit's UI, theme and validation specs still run. Audio continuity is covered by Chromium and Firefox; branded Safari still needs a manual check.

### Playwright artifacts

- `playwright-report/` and `test-results/` are ignored.
- Traces are captured on first retry; screenshots only on failure.
- CI retries twice and uploads reports on failure.

## Screenshots

```bash
npm run build
npm run preview
# in another terminal
npm run screenshots
```

This captures the three README screenshots from the driven production interface. Use `SCREENSHOT_URL` to target another running build. The script requires the generated fixtures, which the Playwright global setup also produces; run `npm run fixtures` first if needed.

## Production preview and smoke check

```bash
npm run build
npm run preview
# in another terminal
npm run smoke
```

`vite preview` uses the Cloudflare Vite plugin, so this is a Workers Static Assets preview rather than a plain static file server. The default port is 4173.

To smoke-test a deployment:

```bash
# macOS / Linux
SMOKE_URL=https://your-site.workers.dev npm run smoke

# PowerShell
$env:SMOKE_URL = 'https://your-site.workers.dev'; npm run smoke
```

The smoke script checks the title, privacy statement, empty state, absence of the development hook, file loading, duration, playback progress, A/B switching and pause state, and fails on console or page errors.

## Troubleshooting

### A Playwright browser is missing

Run the matching `npx playwright install <browser>`. CI installs Chromium with `--with-deps` on Ubuntu.

### Port 4173 is already in use

Playwright starts its server with `--strictPort`; stop the process using 4173. For manual previews, pass another port:

```bash
npm run preview -- --port 8787
```

Then set `SMOKE_URL` or `SCREENSHOT_URL` to that port.

### Motion logs a reduced-motion warning

If the host OS has reduced motion enabled, Motion prints a console warning in development. It is informational. The Playwright reduced-motion spec deliberately emulates the preference, and decorative animations are then skipped.

### Theme looks wrong after an experiment

Clear the only persisted key:

```js
localStorage.removeItem('switchroom.theme');
```

Reload afterwards. With no stored value, the app follows the operating-system preference.

### File loads fail unexpectedly

Remember that the extension is only a hint. The browser must decode the codec inside the file. Try a PCM WAV or MP3 to separate app issues from codec support. The slot error names the affected version and the interface stays usable.

### Deployment authentication

`npx wrangler whoami` reports whether Wrangler is authenticated. See [deployment](deployment.md); never put tokens in source files or paste them into chat.

## Repository hygiene

- Never commit personal audio, generated fixtures, `.env*` files, tokens or `dist/`.
- `.gitignore` covers build output, Wrangler state, test artifacts, local env files and the fixture folder.
- The theme preference is the only browser storage the app writes.
